# M2：物理の性能測定基準

M2完了版は[最新の36ケース](./m2-final.json)と[安息角24ケース](./m2-repose.json)を参照してください。以下の変更前後の比較は、物質登録・表面緩和を追加する前の履歴として保存しています。

固定seedと固定tick数で、変更前後の物理挙動と処理費用を比較します。測定結果はGit管理し、速度をCIの合否条件にはしません。

## 測定条件

- サイズ：365×365、640×360、1280×720。
- シーン：落下中の砂、静止した石、移動中の水、火・油・水・酸・石の反応。
- seed：`0x434841524f4e`。シーンの準備と初期化は計測外。
- シーンごとに16 tickを12回測定。毎回同じ状態へ戻し、最初の1回はウォームアップとして除外する。
- tickごとに経過時間を計測し、平均・中央値・p95・最大値を記録する。
- `kernel`：物理のstepのみ。
- `simulation_snapshot`：Simulationのstepと公開用snapshotの生成・解放。
- `plugin_snapshot`：開始済みAppのPlugin更新と最新snapshotへの置き換え。要求キューは空で、Clientは生存している。

描画・GPU・ウィンドウ・実行スレッドの待機・外部コリジョン・操作要求の処理は測定に含めません。計算レーンを単独で測るための基準であり、ゲーム全体のFPSや、どのような世界でも同じ負荷になることを保証するものではありません。シーンは短い更新区間の観測です。

### 記録環境

2026-10-25、Linux x86_64 / AMD EPYC 9V74、利用可能な論理CPU数3、Rust 1.99.1、releaseプロファイル。共有実行環境のため、CPUの割り当てやOSのスケジューリングによる揺れがあります。詳細と日時は各JSONに保存しています。

- [変更前：全セルコピー](./m2-copy-baseline.json)
- [変更後：バッファ受け渡しと休止時の省略](./m2-buffer-handoff.json)

両方とも同じ測定ツールと準備処理を使います。変更前のphysics本体は `b07c21e` 版です。新しい測定ツールと共通ヘルパーを導入した作業ツリーで測定しているため、`dirty: true` です。`git_head` だけで測定対象を判断せず、同時に記録した `physics_source_sha256` と保存された実装を参照してください。

## 処理時間の予算

| レーン | 目標 | 1更新の時間幅 | 今回の扱い |
| --- | --- | --- | --- |
| ゲーム | 144Hz | 約6.94ms | この測定の対象外 |
| 描画 | 60Hz | 約16.67ms | この測定の対象外 |
| 計算 | 60Hz | 約16.67ms | Plugin更新のp95を8.33ms以内に収めることを暫定目標とする |
| 計算 | 30Hz | 約33.33ms | Plugin更新のp95を16.67ms以内に収めることを暫定目標とする |

計算の時間幅の半分を、将来の照明、アダプター、入力処理、負荷の揺れなどの余裕として残します。現状のケースは変更後にこの暫定目標内でしたが、他のCPU・実機・シーンでの達成は別途確認が必要です。

## 比較結果

単位はms、すべてp95です。公開用snapshotの費用を含むPlugin経由の値を、物理単体の値と分けて示します。

| 365×365 | 静止地形 | 0.0080 | 0.000070 | 0.0142 | 0.0059 |
| 365×365 | 液体 | 0.5515 | 0.5596 | 0.5549 | 0.5477 |
| 365×365 | 反応 | 1.0814 | 1.0844 | 1.0213 | 1.0632 |
| 640×360 | 砂の落下 | 0.5050 | 0.4972 | 0.5804 | 0.5828 |
| 640×360 | 静止地形 | 0.0155 | 0.000190 | 0.0900 | 0.0785 |
| 640×360 | 液体 | 0.9143 | 0.8996 | 0.9776 | 0.9933 |
| 640×360 | 反応 | 1.7519 | 1.7753 | 3.5629 | 1.7994 |
| 1280×720 | 砂の落下 | 1.8157 | 1.8082 | 2.2365 | 2.2163 |
| 1280×720 | 静止地形 | 0.0746 | 0.000521 | 0.4483 | 0.3462 |

静止地形では、物理の全セルコピーとセル単位の初期化を省ける効果が見られました。一方で、Pluginは現在も毎tickのsnapshotを作るため、そのコピー・割り当て・解放の費用が残ります。

動いているシーンでは、移動・反応の処理が主体です。すべての条件で速くなるという結果ではありません。1280×720の反応シーンではPlugin経由のp95が約6.45msから約6.90msへ増えており、中央値は両方とも約6.21msでした。今回の時間測定だけから、普遍的な高速化や退行率を断定しません。

## メモリと更新対象

`Grid::buffer_bytes()` はセル2本、movedフラグ、チャンク2本の**確保済みVecの内容領域**を合計します。構造体ヘッダー、アロケーターの管理領域、スナップショットを保持する読み手、外部固体の集合は含みません。`Vec<bool>` はRustでは1要素1バイトとして計算しています。

| サイズ | GridのVec内容領域 | snapshot 1枚のセル領域 | 合計 |
| --- | ---: | ---: | ---: |
| 365×365 | 666,413 B | 266,450 B | 0.89 MiB |
| 640×360 | 1,152,480 B | 460,800 B | 1.54 MiB |
| 1280×720 | 4,609,840 B | 1,843,200 B | 6.15 MiB |

1280×720ではGridと公開snapshot 1枚のVec内容領域を8MiB以内にすることを暫定目標とし、現在は約6.15MiBです。変更前後でセル構造とバッファ容量は増えていません。公開中・生成中のsnapshotや読み手が保持する古いsnapshotは別にメモリを使うため、これはプロセス全体の上限ではありません。

各JSONには処理したアクティブチャンク数の平均・最大と、Linuxで取得できた場合の測定プロセス全体のpeak RSSも記録します。peak RSSには測定用の初期グリッド・クローンなども含まれ、1ワールド分のメモリとは区別します。

## 採用した変更と互換性

更新ルールはworking bufferだけを参照するため、計算の前後で割り当てを交換して、従来の全セルコピーをなくしました。アクティブチャンクがないtickは、チャンク管理を更新した後で戻ります。

`cells` は呼び出し前後とも現在の状態です。`next` は作業・予備領域で、前フレームの履歴ではありません。履歴が必要な呼び出し側は明示的なsnapshotを保持してください。公開snapshotのコピーや、更新中のmovedフラグの処理は引き続き残っています。

従来のコピー方式をテスト内の参照実装として残し、異なるサイズ・粒子移動・反応・外部編集・チャンク境界について、各tickのセル状態、乱数ストリーム、チャンク状態を比較します。保存した36ケースの最終セルチェックサムとチャンク推移も変更前後で一致しています。

## 再測定

Rust導入済みのWindows 11などで、リポジトリのルートから実行できます。

```powershell
cargo run --release -p charon-bench -- --output physics-profile.json
```

測定時間を調整する場合：

```powershell
cargo run --release -p charon-bench -- --trials 24 --ticks 32 --output physics-profile.json
```

Pythonも利用できる場合は、CPU・OS・Rust・ソース指紋を含む記録を生成できます。

```powershell
python scripts/profile_physics.py --output physics-profile-with-environment.json
```

保存済みの比較データの整合性確認：

```powershell
python scripts/check_physics_profiles.py
```

測定値は初期状態、tick数、測定ツール、release設定、環境をそろえて比較します。CIではデータの整合性と挙動のテストを確認し、実時間のしきい値は判定しません。安息角と物質登録の評価は下記のM2完了記録にまとめています。速度・慣性は今後の拡張です。

