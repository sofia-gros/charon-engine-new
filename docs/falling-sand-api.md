# M2：Falling Sand API

物理を単体利用する `charon_physics` と、Coreへ接続する `charon-sand` を分けています。描画・Tilemap・GPUへの依存はありません。M2では物質登録・独自更新・安息角も実装しています。[物質API](./materials.md)を参照してください。

## 独立した物理API

既存の `Grid` と `physics::step` は維持しています。新しい `sim::simulation::Simulation` は、seed、要求処理、外部コリジョン、読み取り用スナップショットをまとめます。

- `Simulation::new(width, height, seed)`：空の物理世界を作る。幅・高さは正の値。
- `apply(Request)`：要求IDと任意の期待リビジョンを確認して操作し、`Receipt` を返す。
- `step()`：物理を1 tick進める。停止中は進めない。
- `grid()` / `is_solid()` / `contacts()`：セル、外部固体、接触を読み取る。
- `snapshot()`：セルと外部コリジョンを分けた読み取り用コピーを作る。

`CellData` は2バイトを維持します。外部コリジョンは別の疎な集合に格納し、セルの物質として保存しません。既存の移動・反応ルールを利用するため、計算中だけ空の外部固体位置を反応しないBlockで覆い、計算後に粒子レイヤーから取り除きます。外部固体を追加するときは既存粒子との重なりを拒否するため、覆う操作で粒子を破壊しません。

この方式は単純な接続基盤です。外部固体の数に比例する処理があり、物理内部の全セルコピーは削除しましたが、公開用snapshotの作成にはコピーが残ります。正式なTilemapは未実装で、このAPIを使うBridge PluginはM3で作ります。

## 要求と結果

| Operation | 処理 |
| --- | --- |
| `Brush` | 円形範囲の空セルに物質を置く。Airを指定すると物理セルを明示的に消去。外部固体は消去しない |
| `Collider` | 矩形範囲の外部固体を追加・解除。追加先に粒子がある場合は全体を拒否 |
| `Release` | 矩形内に存在する外部固体を、1位置につき1セルの指定物質に変換 |
| `SetRepose` | 登録した粒状物質の角度を変更し、休止領域を起こす。無効な値はInvalidSettings |
| `SetPaused` | 物理のtick進行を停止・再開。停止中も編集要求は処理する |
| `Reset` | セルと外部固体を消去し、乱数seedとtick数を初期化。要求IDと登録定義・物質設定は維持 |

矩形やブラシはワールドの範囲でクリップします。座標の変換や複数セルからなるタイルは、呼び出す側が担当します。

要求IDは一つのSimulationに対して単調増加させます。複数のClientや生成元がある場合も、採番と送信順序を一か所に集約してください。以前のIDは `DuplicateOrOutOfOrder` として再適用しません。受理したIDは、期待リビジョン違いや占有による失敗でも消費します。再試行で操作を再評価したい場合は新しいIDを使用してください。

`revision` は変更があった操作と物理tickで増加します。`expected_revision` が一致しなければ変更しません。Resetでもrevisionは巻き戻しません。

ReceiptにはID・確定revision・結果・変更数・ブラシで処理できなかった数を含めます。`Release` の変換量は実際に存在した外部固体の数です。水や砂を無条件に上書きして量を失うことはしません。

## Coreへの接続

`FallingSandPlugin::new(simulation, capacity)` は、Pluginと `SandClient` を返します。Pluginを計算用Workerに登録し、ゲーム側はClientを使います。

- `SandClient::try_send()`：上限付きキューに要求を入れる。満杯なら元の要求を返すので、保持して再試行できる。
- `try_receipt()`：確定結果を取り出す。Clientを複製しても、結果を取り出す読み手は共通のキューを消費する。
- `snapshot()`：最新の `Arc<Snapshot>` を取得する。読む間に物理世界をロックし続けない。
- `SandState`：同じ計算用Appの後続Pluginから、物理状態と接触を参照する。

要求は1 tickあたり最大64件処理します。結果キューが満杯の場合は結果を1件保持し、追加要求の処理を止めます。物理計算は続行します。受付・結果とも黙って捨てず、結果の読み手が停止した場合にもメモリを無制限に増やしません。

同じWorldには `Receipt` イベントも発行します。これは固定tickごとのブロードキャストで、次の固定tick冒頭に消去します。下流のPluginは `dependencies()` で `falling-sand` より後に実行してください。

接触は `Simulation::contacts()` で取得できます。Worldへの通知が必要なら `.with_contact_events(limit)` を指定します。これはそのtick時点の接触のサンプルで、接触開始・終了だけを通知する方式ではありません。上限を超える場合は `ContactOverflow` イベントを発行します。既定では接触イベントを生成しません。

終了時は状態を解放し、要求・結果チャンネルを閉じます。終了前の未処理要求は確定済みではありません。終了前に結果の確認が必要なら、呼び出し側で受理したIDの結果を待ってから停止します。取得済みスナップショットは読み取り可能なまま残ります。

## 時間と費用

ゲーム144Hz、描画60Hz、計算30〜60Hzは独立しています。現時点の物理は従来のtick単位のセルオートマトンで、計算Hzを変えると実時間あたりの落下速度や寿命も変わります。時間幅に合わせた物理パラメータの補正は未実装です。

物理内部の全セルコピーは削除し、休止時はセルの走査を省きます。公開用スナップショットは毎計算tickで引き続きコピーし、登録名・色・移動特性・角度のpaletteも含みます。描画側のArc取得は小さな操作ですが、発行側のメモリ処理はグリッドサイズに比例します。固定シーンの[性能測定結果](./performance/README.md)を記録していますが、ゲーム全体や全環境での性能目標を達成済みとはしません。安息角・マテリアル設定はM2で実装済みです。公開snapshotの最適化、速度・温度などの追加物理は今後の拡張です。

## 検証

```powershell
cargo test -p charon-sand
cargo run -p charon-m2-sample --no-default-features -- --smoke-test
cargo tree -p charon_physics --edges normal
cargo tree -p charon-core
```

単体利用とPlugin経由の結果一致、外部コリジョン、チャンク境界の解除、質量保存、二重適用の拒否、結果キューのバックプレッシャー、部分初期化失敗時のリソース所有権を確認します。
