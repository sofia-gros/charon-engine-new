# Tilemap / Falling Sand 接続APIの設計

この文書はM2・M3で実装する接続APIの契約です。M1時点では、Tilemap本体とこのAPIの実装はまだありません。

## 使い方の目標

タイルマップで地形を構築し、ゲーム側がブロックを破壊したときに、設定に応じて砂や水などのセルを生成します。タイルの隙間へセルが流れ込み、残っているブロックには衝突します。砂の堆積や水の接触を、タイル設置・破壊やゲーム側の処理にも反映できます。

Tilemap単体、Falling Sand単体、両者を接続した構成をそれぞれ維持します。接続処理は、双方の公開APIを使う任意のBridge Pluginに置きます。Core、Renderer、Tilemap、Falling Sandの内部に相手の実装を埋め込みません。

## 公開する契約（実装予定）

| APIの役割 | 入出力・責務 |
| --- | --- |
| 座標・領域変換 | タイル座標・物理セル座標・ワールド座標を変換。原点、セル幅、タイル幅、負座標と境界を定義 |
| 静的コリジョンの取得 | Tilemapから、指定領域の占有・衝突形状とリビジョンを取得 |
| 動的コリジョンの取得 | Falling Sandから、指定領域の粒状物質・液体の占有や接触情報を取得 |
| 地形変更要求 | ブロックの設置・破壊をコマンドID・期待リビジョン付きで要求 |
| 粒子の生成・除去要求 | 砂・水・その他の物質を、範囲と量を指定して操作 |
| 破壊時の変換規則 | どのタイルを、どの物質・量へ変換するかをゲーム側が登録 |
| 変更結果・接触通知 | 実際の生成量・残量、失敗理由、変更領域、新しいリビジョン、接触イベントを返す |

これらの名前やRustの型は実装時に確定します。接続APIは描画を必要とせず、照明用の光学データ変換とも別の責務です。

## 双方向コリジョン

- Falling Sandの移動判定は、接続されたタイルの衝突形状を参照し、固体タイルを通り抜けない。
- Tilemap側の設置判定も、動的セルの占有を参照する。
- セルがある場所へのタイル設置は「拒否」「周囲へ押し出す」「対応物質を固化する」など、明示した規則に従う。粒子を暗黙に消さない。
- 衝突・接触によるタイルの損傷や破壊は、ゲーム側の規則として追加できる。接触しただけで自動破壊することは前提にしない。
- 水の通過可否、砂の支持、対象レイヤーなどは、表示上のタイル画像とは分けて設定する。
- 物理セルとタイルは1対1と仮定しない。1タイルが複数セルを覆う構成も扱う。

## スレッドと更新境界

ゲームは144Hz、計算は30〜60Hz、描画は60Hzを目標にします。各所有スレッドの状態を直接書き換えず、コマンドとスナップショットで接続します。

1. ゲーム側が、破壊・生成・設置などの要求を送る。
2. 計算境界で期待リビジョンを確認し、タイルのコリジョン変更と対応する粒子変換を一つの処理として適用する。
3. 適用結果と、新しいコリジョン・セルのスナップショットを公開する。
4. ゲームと描画は、同じ確定リビジョンの結果を受け取る。

計算中に古いタイル状態と新しいセル状態を混在させません。ゲーム側は応答前の操作を保留状態として扱えます。操作から反映まで最大1計算間隔程度の遅延が生じ得るため、補間や先行表示を行う場合も確定状態とは区別します。過負荷時の遅延は計測し、上限や受付制限を設けます。

状態の所有者を一つに定め、破壊・変換を二重に確定させないようにします。信頼性が必要な変更要求と結果は、上限付きキューと受付結果で管理し、満杯なら再試行または拒否を返します。破壊・生成を黙って捨てません。表示用スナップショットは古いものを最新のものへ置き換えられます。

## 実装時の確認項目

- Tilemapのみ・Falling Sandのみのビルドと実行が成立する。
- 接続時も物理・TilemapがRendererに依存しない。
- ブロックを壊すと規則どおりの砂・水が生成され、隣のブロックで止まる。
- コマンドの再送で粒子が二重生成されない。
- 生成先が埋まっているときの残量・失敗を返し、質量を無断で失わない。
- 動的セルがある場所へのタイル設置で、指定した衝突解決規則が働く。
- サイズ比の違い、負座標、ワールド境界、チャンク境界を扱える。
- ゲーム144Hz・描画60Hz・計算30Hz / 60Hzでも、変換量やコリジョンの整合性が保たれる。
